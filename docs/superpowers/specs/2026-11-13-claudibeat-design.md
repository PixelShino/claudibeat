# claudibeat: дизайн

Дата: 13.11.2026. Статус: черновик, ждёт утверждения владельца.

claudibeat — маленькая программа для Windows 11. Она живёт в левом углу панели задач и показывает пульс сессий Claude Desktop и памяти компьютера.

## Зачем

Владелец ведёт много сессий Claude Desktop одновременно, иногда 40 и больше. Сессия, которая закончила работу или ждёт ответа, теряется: чтобы её заметить, надо держать приложение Claude перед глазами. Вдобавок Claude со своими MCP-серверами и терминалами съедает много памяти. Сейчас это около 15 ГБ из 32, хотя диспетчер задач показывает у самого `claude.exe` всего 6.

Нужен один взгляд в левый нижний угол экрана, чтобы понять:

- сколько сессий сейчас работает;
- сколько ждут ответа владельца;
- сколько закончили, но ещё не открыты;
- сколько памяти занято и кто её ест;
- сколько осталось лимита Claude (это второстепенно, владелец может это убрать).

Когда сессия закончила работу или ждёт ответа, должно появиться короткое уведомление. Клик по нему открывает этот чат.

## Цели

1. Полоса слева на панели задач основного монитора: значки и цифры (вариант C на макетах).
2. Окно по клику на полосу: списки сессий по группам, разбивка памяти и лимиты.
3. Уведомления «ждёт ответа» и «готово». По клику открывается нужный чат в Claude Desktop.
4. Чёрно-белое оформление в светлой теме, которое не выбивается из Windows 11.

## Не цели (в v1)

- Субагенты. Их не считаем вообще: «в работе» — это сессия, а не агент внутри неё.
- Задачник Plane, стоимость в токенах, несколько аккаунтов, облачные сессии.
- Тёмная тема и второй монитор. Сейчас у владельца один экран 1920×1080 и светлая тема. Код не должен мешать добавить их позже.
- Замена CodeZeno Usage Monitor и полосы status-band внутри Claude. claudibeat их дополняет.

## Анти-цели (технически работает, но это провал)

- Цвет. Только оттенки серого, громкий элемент один: чёрная отметка «ждёт».
- Вытянутые «таблетки». Владелец их не принял, выделение делается квадратом или кругом.
- Шум: уведомление на каждую мелочь, два уведомления на одно событие, уведомления пачкой при запуске.
- Ложный статус, например «в работе» у мёртвой сессии.
- Риск для панели задач: никакого внедрения кода в `explorer.exe`. Если claudibeat упадёт, панель должна остаться целой.
- Сеть и токены: claudibeat никуда не ходит и не читает OAuth-токен Claude.
- Заметная нагрузка: в простое не больше 1 % CPU и не больше 40 МБ памяти.

## Ограничения

- Windows 11 Pro 25H2, сборка 26200, 1920×1080 при масштабе 100 %, светлая тема. Панель задач по центру, высота 48 px, поле поиска скрыто, левый угол пуст (виджет погоды выключен).
- Сборщиков почти нет: нет .NET SDK и нет Visual Studio Build Tools, поэтому Rust не линкуется. Есть встроенный в Windows компилятор C# `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (.NET Framework 4.8, язык C# 5), а также Python 3.14 и Node 26.
- Правила владельца: `git push` никогда. Живой рабочий стол не трогать: проверять отрисовку картинками без окон, а запуск на живой панели делать только после явного «да» владельца на конкретный запуск. Автозапуск включается только с его согласия.

## Подходы

| Подход | Плюсы | Минусы | Итог |
|---|---|---|---|
| **Своя программа, встроенная в панель** (окно-потомок `Shell_TrayWnd`, как у CodeZeno и TrafficMonitor) | Левый край; падение программы не роняет панель; полный контроль над видом | Больше всего работы; встраивание надо переживать при перезапуске Explorer | **Выбран владельцем** |
| Мод Windhawk внутри `explorer.exe` | Выглядит роднее всего | Ошибка мода роняет всю панель; отлаживать можно только на живом рабочем столе | Отклонён |
| Трей из плана status-band от 03.11 (Python, значок у часов) | Дешевле всего, дизайн уже был | Справа у часов, а не слева | Отклонён: не даёт главного |

## Что решено

### Источник данных о сессиях

Источник — контракт v1 мода status-band. Его описание лежит в `~/.claude/mods/status-band/docs/DESIGN.md`, данные в `%USERPROFILE%\.claude\status-band\`.

- `index.json`: все сессии Desktop с полями `desktopId`, `title`, `isRunning`, `lastActivityAt`, `link` (`claude://claude.ai/epitaxy/local_…`).
- `sessions/<key>.json`: состояние сессии `working | waiting | done | idle`, а ещё `stateSince`, `heartbeatAt`, `ask` (текст вопроса), `doing`, `project`, `waitingReason`. Массив `agents` claudibeat не читает.
- `acks/<key>.json`: отметка «просмотрено» `{ "v": 1, "ackAt": <мс>, "by": "…" }`.
- `account.json`: лимиты `limits[]` с полями `window` (`five_hour`/`seven_day`), `percent` (израсходовано) и `resetsAt`.

Сведение данных идёт по тем же правилам, что у полосы status-band:

1. Сессии = объединение `index.json` и `sessions/*.json` по `desktopId`. Сессия без файла получает `working`, если `isRunning`, иначе `idle`.
2. Если `heartbeatAt` старше 90 с, состояние берётся из индекса.
3. **Ждёт** = `waiting` без ack, у которого `ackAt ≥ stateSince`. **Готово** = `done` с тем же условием. **В работе** = `working`.
4. «Всего» = сессии из индекса, исключая архивные и те, что простаивают дольше 24 ч.

Файлы пишутся атомарно (tmp, затем переименование), но читатель обязан переживать полузаписанный JSON: при ошибке разбора берётся прошлое значение.

**Открыть чат** = `ShellExecute` по `link` сессии, затем атомарно записать `acks/<key>.json` с `"by": "claudibeat"`. Отметка общая с полосой внутри Claude: что владелец открыл там, здесь больше не напоминает, и наоборот.

### Память

- Всего занято / всего есть: из `GlobalMemoryStatusEx`.
- Группы в окне по клику:
  - **Claude с MCP и терминалами** = все процессы `claude.exe` плюс все их потомки по дереву родителей. Это node, python, cmd, conhost, powershell, bash, запущенные Claude.
  - **Chrome** = `chrome.exe` и его потомки вне группы Claude.
  - **Python вне Claude** = `python*.exe` вне группы Claude.
  - **Остальное** = занято минус три группы выше.
- Число на полосе: процент занятой памяти. При значении от 85 % значок памяти заливается чёрным.

### Лимиты (второстепенно, можно будет выключить)

- Кружок и процент **оставшегося** лимита, как у батарейки: владелец просил именно «сколько осталось». Подсказка: «Осталось 34 %, израсходовано 66 %, сброс вс 18:00».
- Из двух окон (`five_hour`, `seven_day`) на полосе показывается то, где осталось меньше. В окне по клику видны оба.
- Если `account.json` старше 6 ч или окна нет, кружок бледный, вместо числа стоит «–».

### Полоса на панели (вариант C)

Порядок слева направо: `ждёт · готово · в работе | память · лимит`. Точки здесь условные, на полосе их нет.

| Элемент | Значок | Подсказка при наведении |
|---|---|---|
| Ждёт | закрашенная точка | «1 сессия ждёт ответа» |
| Готово | галочка в круге | «2 сессии закончили, не открыты» |
| В работе | **выбор владельца по макету v2**, моё предложение — звёздочка, как у Claude Code во время работы | «4 сессии в работе» |
| Память | чип памяти (контур, от 85 % залит) | «Занято 24,2 из 31,8 ГБ» |
| Лимит | кольцо | «Осталось 34 % недельного лимита, сброс вс 18:00» |

- Шрифт Segoe UI Variable, 13 px, полужирные цифры одинаковой ширины. Цвет текста `#1b1b1b`, второстепенный `#5d5d5d`, чистые чёрный и белый не используются.
- Нулевые значения бледнеют до 42 %, но не исчезают, чтобы ширина полосы не прыгала.
- **Выделение «ждёт»: выбор владельца по макету v2.** Варианты: (1) чёрный квадрат со скруглением 6 px вокруг значка и цифры; (2) число в чёрном круге 22 px, круг остаётся кругом и для двузначных чисел.
- Наведение мыши: подложка `rgba(0,0,0,0.05)` со скруглением 6 px, как у кнопок самой панели.
- Левый клик по «ждёт» или «готово»: если там ровно одна сессия, сразу открыть её чат, иначе открыть окно. Клик по остальным элементам открывает окно.
- Правый клик открывает меню: «Отметить всё просмотренным», «Звук уведомлений» (вкл/выкл), «Запускать вместе с Windows» (вкл/выкл), «Выход».
- Место: левый край панели основного монитора, отступ 8 px, по центру по вертикали. Высота элемента 32 px, область клика 40 px.

### Окно по клику

Макет: `docs/mockups/v1/flyout.png`.

- Ширина 384 px, окно открывается над полосой и выровнено по её левому краю. Скругление 8 px, системная тень, фон `#f9f9f9`.
- Заголовок «Сессии Claude», справа «N всего».
- Группы по порядку: «Ждут ответа» (с текстом вопроса в кавычках), «Готово, не открыто» (с названием проекта), «В работе» (с тем, что сессия делает сейчас). В группе не больше 3 строк, остальное сворачивается в «и ещё N». Прокрутки нет. Пустая группа не показывается.
- Строка: значок, название (одна строка, многоточие), подпись, справа время в состоянии («7 мин»). Клик по строке открывает чат и ставит отметку.
- Ниже идут «Память» (общая полоса и четыре группы с полосками) и «Лимиты» (два кольца со временем сброса).
- Окно закрывается по Esc, клику мимо или повторному клику по полосе.

### Уведомления

Макет: `docs/mockups/v1/toast.png`.

- Собственные окна над полосой, слева, не больше 3 одновременно, новое появляется снизу.
- «Ждёт ответа»: висит, пока его не откроют или не закроют. «Готово»: исчезает через 8 с, при наведении таймер стоит.
- Клик открывает чат и ставит отметку. Крестик только закрывает уведомление, отметку не ставит, счётчик остаётся.
- Уведомление появляется только при переходе сессии в `waiting`/`done` на глазах у программы. При запуске уже ждущие сессии уведомлений не дают. Одной сессии не чаще раза в 10 с. Сессии, открытой из claudibeat в последние 5 с, уведомление не показывается.
- Звук: короткий мягкий свой `.wav`, не системный. Выключается в меню.

### Как сделано

- C# на .NET Framework 4.8 (C# 5), сборка скриптом `build.ps1` через встроенный `csc.exe`, без NuGet и установок. Результат: `bin\claudibeat.exe`.
- Полоса — окно-потомок `Shell_TrayWnd` (`SetParent`, `WS_CHILD`). Оно заново встраивается по сообщению `TaskbarCreated` после перезапуска Explorer. Учитываются автоскрытие панели и полноэкранные приложения. Образец встраивания с открытым кодом: CodeZeno Claude-Code-Usage-Monitor (MIT), `native_interop.rs` и `positioning.rs`.
- Окно и уведомления — обычные верхние окна, нарисованные вручную, со скруглением и тенью Windows 11 через DWM (`DWMWA_WINDOW_CORNER_PREFERENCE`).
- Обновление: следить за папкой status-band через `FileSystemWatcher` и раз в 2 с перечитывать на всякий случай. Память опрашивать раз в 3 с.
- Автозапуск: значение в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, по умолчанию выключен.

### Главный технический риск

Фон панели в Windows 11 полупрозрачный (Mica) и меняется вместе с обоями. Окну-потомку на панели нужен прозрачный фон с попиксельной альфой, а текст на таком фоне должен быть сглажен без цветной окантовки. Поэтому **первым шагом нужен пробный прототип**:

1. Встроить окно-потомок слева.
2. Нарисовать в нём текст и значки на прозрачном фоне.
3. Пережить перезапуск Explorer.

Запуск прототипа на живой панели — только после «да» владельца. Если прозрачность не получится, запасной вариант такой: окно-потомок с непрозрачным фоном, цвет которого берётся из пикселей панели под ним.

## Проверка

- Логику сведения сессий, подсчёт групп памяти и правила уведомлений проверяет отдельная тестовая сборка на подготовленных JSON-файлах.
- Полосу, окно и уведомления программа умеет отрисовать в PNG без окна (ключ `--render <файл>` с тестовыми данными). Эти снимки сверяются с макетами глазами.
- Живая проверка на панели проходит после «да» владельца и снимается снимком полосы.

## Оставлено исполнителю

Структура модулей, способ рисования (GDI+ или Direct2D через interop), точная метрика памяти (ориентир: как столбец «Память» в диспетчере задач, расхождение не больше 10 %), тексты меню, звук уведомления, формат логов.
