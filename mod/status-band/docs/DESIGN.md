# status-band — полоса статуса Claude, трей Windows и задачник Plane

Дата: 03.11.2026. Владелец решил: задачник общий, метка = проект Plane; при «ждёт / закончил» — отметка и звук; в панели задач Windows — значок в трее и текст у часов.

## Невидимость (17.11.2026)

Владелец решил: мод ничего не рисует, он только поставщик данных. Хуки `ui.render` для `AbovePrompt`, `SessionMode` и `PromptHint` остались лишь чтобы запустить тикер в сессии, где не сработал `session.start`, и всегда отдают `next(e)`. Тостов, звука и синей точки в сайдбаре у мода нет: их делает claudibeat. Разделы ниже про рисование на десктопе, трей и звук — история; действуют контракт папки, Plane, инструмент `backlog` и заявки доски.

## Зачем

Владелец ведёт много сессий Claude параллельно. Сессия, которая ждёт ответа или закончила, теряется в сайдбаре, и он её не видит. Нужен один взгляд на всё: какие сессии ждут, какие работают, что делают их агенты, сколько осталось лимитов, и задачник, из которого Claude сам берёт работу.

## Части

| Часть | Где | Что делает |
|---|---|---|
| Мод `status-band` | `~/.claude/mods/status-band/` (`hooks/`) | В каждой сессии пишет её состояние в общую папку; рисует полосу над полем ввода (`AbovePrompt`); ходит в Plane; даёт модели инструмент `backlog` |
| Трей `status-tray` | `~/.claude/mods/status-band/tray/` | Python: значок в трее с цифрой, всплывающее окно, звук и уведомление Windows, строка для часов на `127.0.0.1` |
| Текст у часов | Windhawk, мод «Taskbar Clock Customization» | Ставит владелец; берёт строку у трея через `%web1%` |

Анти-цели: правая панель для статуса; полоса выше одной строки в свёрнутом виде; ложный статус («работает» у мёртвой сессии); звук на каждую мелочь или дважды на одно событие; ключ Plane в логах, файлах или выводе; заметная нагрузка (опрос чаще раза в 2–5 с).

## Общая папка и формат (контракт v1)

Корень: `%USERPROFILE%\.claude\status-band\` (`STATUS_DIR`). Каждый файл пишет ровно один владелец. Запись атомарная: сначала `<имя>.tmp`, потом переименование; если переименования нет, читатель обязан переживать полузаписанный JSON (ошибка разбора = взять прошлое значение). Время везде в мс эпохи (UTC). Все строки для показа уже обрезаны писателем.

### `sessions/<key>.json` — пишет мод своей сессии

`<key>` = десктопный id (`local_…`), если мод его узнал, иначе `cli-<id движка>`.

```jsonc
{
  "v": 1,
  "key": "local_68dc…",
  "desktopId": "local_68dc…",        // null, если не удалось узнать
  "cliId": "e4afbbbe-…",
  "title": "Панель статуса и задачник", // null → показывать проект
  "cwd": "D:\\Code\\Projects\\my-app",
  "project": "my-app",              // имя папки; scratch-папки приложения → "без папки"
  "link": "claude://claude.ai/epitaxy/local_…", // null, если неизвестна
  "state": "working",                 // working | waiting | done | idle
  "waitingReason": null,              // question | permission | decision | null
  "ask": null,                        // текст вопроса ≤ 140 знаков, когда waiting
  "stateSince": 1762176000000,
  "doing": "запускает тесты",         // ≤ 80 знаков, только при working
  "context": { "percent": 38, "tokens": 380000 },
  "agents": [
    { "id": "a1", "type": "Explore", "model": "haiku-4.5", "status": "running",
      "doing": "ищет вызовы enrich()", "startedAt": 1762175900000, "endedAt": null }
  ],
  "heartbeatAt": 1762176010000        // раз в 15 с; старше 90 с = сессия офлайн
}
```

Состояния: `working` — идёт ход модели; `waiting` — ход закончен вопросом (`AskUserQuestion`, `wrap_up` с `blocked: true` или с `ask`), запросом разрешения или уведомлением «нужен ввод»; `done` — ход закончен без вопроса; `idle` — владелец ответил или открыл, ждать нечего.

### `index.json` — пишет один мод-лидер (замок `index.lock`, TTL 20 с)

Список всех сессий приложения из `list_sessions`, раз в 10 с: даёт сессии, где мод не загружен.

```jsonc
{ "v": 1, "updatedAt": 0, "sessions": [
  { "desktopId": "local_…", "title": "…", "cwd": "…", "isRunning": true,
    "lastActivityAt": 0, "link": "claude://…", "pinned": false } ] }
```

### Заявки доски claudibeat (дополнение 17.11.2026)

Спека: `D:\Code\Projects\claudibeat\docs\superpowers\specs\2026-11-17-plane-board-design.md`.

| Файл | Пишет | Читает |
|---|---|---|
| `assignments.json` | мод (лидер) | claudibeat, мод |
| `requests/<id>.json` | claudibeat; claudibeat же удаляет | мод |
| `replies/<id>.json` | мод, который выполнил заявку; удаляет claudibeat | claudibeat |

```jsonc
{"v":1,"id":"cb-1794930000000-a1f3","at":1794930000000,"by":"claudibeat","kind":"assign","task":"WEB-281","target":{"session":"local_<uuid>"}}
{"v":1,"id":"…","at":0,"by":"claudibeat","kind":"assign","task":"WEB-281","target":{"newChat":{"cwd":"D:\\Code\\Projects\\my-app","project":"my-app"}}}
{"v":1,"id":"…","at":0,"by":"claudibeat","kind":"move","task":"WEB-281","to":"todo|doing|done|cancelled"}
{"v":1,"id":"…","at":0,"by":"claudibeat","kind":"refresh"}
```

Ответ: `{"v":1,"id":"…","at":0,"ok":true,"text":"WEB-281 → «Чистка документации»"}`, у успешного `assign` ещё `"task"`, `"session"` (`local_…`; пусто, если новый чат не вернул id) и `"sessionTitle"`. Ошибка: `"ok":false` и короткая русская строка (`Plane недоступен (host)`, `WEB-281 не найдена в Plane`, `…сообщение не доставлено`).

`assignments.json`: `{"v":1,"updatedAt":0,"items":[{"task":"WEB-281","session":"local_<uuid>","sessionTitle":"Чистка документации","at":0}]}`.

Как мод выполняет (код: `hooks/register.tsx` → `serveRequests`, чистая логика — `hooks/board-requests.ts`):

1. Каждые 2 с (`tick`) мод читает имена в `requests/` и `replies/`. Заявку с готовым ответом, уже обработанную этой сессией (память на 500 id), старше 2 минут или не по контракту — не выполняет; на неразобранную лидер отвечает `ok:false` «Заявка не разобрана».
2. Выполняет лидер (держатель `index.lock`). Исключение — `assign` в чат самого лидера: `send_message` не шлёт в собственную сессию, поэтому её выполняет живая десктопная сессия с модом (`isLive`, ключ `local_…`), не лидер, с наименьшим ключом — так два не-лидера не возьмут одну заявку. Если таких нет, лидер вставляет сообщение в своё поле ввода (`$.prompt.fill`) и отвечает «WEB-281 вставлена в поле ввода этого чата».
3. `assign`: `item` (описание) → `move doing` → комментарий «Назначена агенту «<название сессии>» с доски claudibeat» → сообщение по шаблону спеки (без пустого абзаца, если описания нет) → `ccd_session_mgmt.send_message` (успех — в ответе `delivered` или `queued`) или `ccd_session.start_session` (`user_asked`, `fresh`, заголовок `<KEY> <название>` до 56 знаков, `cwd` и `use_worktree:false`, если папка задана) и открытие нового чата по `claude://`.
4. `move` — `move` в Plane; `refresh` — опрос доски, ответ «обновлено». После `assign` и `move` — свежий опрос доски.
5. `assignments.json` пишет только лидер: свои назначения сразу, чужие — из ответов с полями `task`/`session`/`sessionTitle`. После каждого успешного опроса задачи, которых нет в «В работе», убираются (кроме назначенных после начала этого опроса).
6. Ни одна ошибка не роняет `tick`: каждая заявка в своём `try`, ошибки Plane — первой частью сообщения `PlaneError`.

### `tray.json` — пульс трея; пишет трей раз в 10 с

```jsonc
{ "v": 1, "at": 0 }
```
Мод больше не читает пульс и звук не играет никогда (с 17.11.2026).

### `index.lock` — замок лидера

```jsonc
{ "v": 1, "owner": "local_…", "at": 0 }
```

### `acks/<key>.json` — «просмотрено»; пишет тот, кто отметил (мод или трей)

```jsonc
{ "v": 1, "ackAt": 1762176020000, "by": "tray" }
```

### Сведение (одинаково в полосе и в трее)

1. Сессии = объединение `index.json` и `sessions/*.json` по `desktopId`; сессия без файла получает `state = isRunning ? working : idle`.
2. Файл с `heartbeatAt` старше 90 с не врёт: его состояние берётся из индекса.
3. **Требует внимания** = `state ∈ {waiting, done}` и нет ack с `ackAt ≥ stateSince`.
4. Порядок: ждут → закончили (не просмотрено) → работают → простаивают (по `lastActivityAt`); простаивающие старше 24 ч и архивные не показываются.
5. Ack ставится: клик по сессии в полосе или трее, сообщение владельца в этой сессии (мод сам переводит её в `idle`), кнопка «Прочитано».

## Где рисовал мод на десктопе до 17.11.2026 (история; сейчас не рисует)

- **Нижняя строка** (`SessionMode`): десктоп рисует собственное дерево мода в полосе слева от выбора модели (`data-engine-footer-strip`), одной строкой, со своим стилем: кнопки становятся серыми чипами приложения и встают первыми, тексты — следом, лишнее обрезается многоточием с подсказкой. Подписи, добавленные в `props.modes`, десктоп выбрасывает (их рисует только терминал). Тут: `1 ждёт` · `2 закончили` · `4 в работе · 15 сессий` · `4 задачи` · `5 ч 41% · неделя 19%`. Чип «ждёт/закончил» с одной сессией открывает её, с несколькими — панель. Контекст не дублируется: у приложения справа своё кольцо.
- **Над полем** (`AbovePrompt`): рамка приложения, высота — `maxRows`, выше — прокрутка. Свёрнуто — только строки «ждёт/закончил» (до трёх, «Открыть»/«Скрыть»), если никто не ждёт — пусто. Раскрыто (чип сессий или задач) — заголовок с вкладками и не больше 9 строк; что не влезло — страницы «‹ Назад · 1 из 3 · Дальше ›», а не прокрутка.
- **Левый сайдбар**: сессия, закончившая ход или ждущая ответа, ставит себе синюю точку непрочитанного (`ccd_sidebar.set_unread self`), если её сейчас не видно на экране (`ccd_view.get_layout` → пустой `views`).
- `PromptHint` десктоп рисует только у облачных сессий (`ccr`), для локальных — нет; там строка-сводка остаётся для терминала.
- Цвета — только ключи темы (`warning`, `success`, `claude`, `error`, `userMessageBackgroundHover`), отступы — токены `xs`/`sm`: десктоп переводит их в свои переменные `--cds-*`, светлая и тёмная тема одинаково.
- Запуск: десктоп ставит `CLAUDE_CODE_ENTRYPOINT=claude-desktop` и `CLAUDE_CODE_HOST_SESSION_ID=local_…`, мод стартует в `session.start` и знает свой id сразу; `claude -p` без них не стартует.

Снимки делаются без окна приложения: тест мода выгружает `ui.drawn()`, страница-стенд рисует деревья функцией приложения из `ion-dist.asar` с его CSS в headless Chrome.

## Plane

- Где Plane: настройки мода (`planeUrl`, `planeWorkspace`, `planeApiKey`), а пустые поля — из `~/.secrets/plane.json` (`base`, `workspace`, `key`; этот же файл могут читать и другие инструменты). Ключ из файла берётся только вместе с его `base`. Последний запасной ключ — `env.PLANE_API_KEY` сервера `plane` в `~/.claude.json`. `inboxProject` — проект для задач без метки, по умолчанию `INBOX`.
- Колонки по группам статусов Plane: `backlog`/`unstarted` → «Не взято», `started` → «В работе», `completed` за сегодня → «Готово сегодня»; `cancelled` не показывается.
- Опрос: при раскрытии вкладки и раз в 60 с, только мод-лидер; кэш последнего ответа в `$.store` для офлайна, с пометкой «данные от HH:MM».
- «Взять в эту сессию»: вставить в поле ввода `Возьми задачу WEB-281: <название>\n\n<описание>` и перевести в первый статус группы `started`, комментарий «Взята в сессию «<название сессии>»».

## Инструмент модели `backlog`

`mcp__status-band__backlog` с `action`: `list` (фильтр по проекту и группе), `show` (`id`), `add` (`title`, `project?`, `description?`), `take` (`id`), `move` (`id`, `to`: `todo|doing|done|cancelled`), `comment` (`id`, `text`). На «чекни задачи» модель зовёт `list`. Ответ — короткий текст, удобный модели.

## Трей

- Значок 16/32 px: круг; серый — всё спокойно, оранжевый с цифрой — кто-то ждёт, зелёный с цифрой — закончили. Подсказка: `2 ждут · 1 закончил · 5ч 41 %`.
- Клик — всплывающее окно у трея (WebView2 через `pywebview`, вёрстка в стиле Claude, светлая и тёмная тема по системе): блок «Требуют внимания», остальные сессии, лимиты, счётчики задач. Клик по сессии → `claude://…` и ack.
- Звук (`winsound`, свой короткий мягкий звук `.wav`, не системный «динь») и уведомление Windows — только при переходе сессии в `waiting`/`done` без ack; не чаще раза в 10 с на сессию; не для сессии, которую владелец открыл через трей последние 5 с.
- `http://127.0.0.1:47321/line` → одна строка для часов, например `● 2 ждут · 5ч 41%`; пусто, если внимания нет и лимиты < 60 %.
- Автозапуск: ярлык в `shell:startup` ставит скрипт `install.ps1` с явного согласия владельца.
